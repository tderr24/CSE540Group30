# PharmaTrace Frontend

React + ethers.js interface for the PharmaTrace supply-chain smart contracts. This app connects to the deployed `Provenance` contract, enforces stakeholder permissions in the UI, and surfaces end-to-end traceability for every pharmaceutical batch.

## Architecture Overview

```
┌────────────────────────────────────────────────────────┐
│ React (CRA)                                            │
│  ├─ WalletConnect (MetaMask, network guard)            │
│  ├─ Role dashboards (Producer → Consumer + Regulator)  │
│  ├─ Product Verification portal                        │
│  └─ Hooks (useAccountProducts)                         │
├────────────────────────────────────────────────────────┤
│ ethers.js                                              │
│  ├─ Reads ABI from `src/contracts/Provenance.json`     │
│  └─ Uses `src/contracts/deployment.json` for addresses │
├────────────────────────────────────────────────────────┤
│ Ethereum RPC (Hardhat localhost / Sepolia testnet)     │
└────────────────────────────────────────────────────────┘
```

- **State sync**: `deployment.json` is generated by Hardhat deploy scripts so the UI always targets the latest contract address/chainId.
- **Wallet support**: MetaMask is required; the app auto-prompts users to switch to the configured chain (local 31337 or Sepolia 11155111).
- **Data model**: Every dashboard calls `useAccountProducts`, which replays `ProductRegistered` events and loads product structs via `getProductDetails`.

## Prerequisites

| Tool | Version | Notes |
| --- | --- | --- |
| Node.js | ≥ 18.x | Aligns with Hardhat + CRA requirements |
| npm | ≥ 9.x | Yarn/Pnpm also work, but npm scripts are committed |
| MetaMask | Latest | Browser extension; required for signing |
| Hardhat | Local dev only | Run `npx hardhat node` if testing locally |

Contract deployment (addresses, ABIs) must exist before the UI can function. Run one of the Hardhat scripts:

- Local: `npm run deploy:local` (creates demo roles/products and writes `frontend/src/contracts/deployment.json`).
- Sepolia: `npm run deploy:sepolia` (requires `.env` with RPC + private key + optional `ADMIN_ADDRESS`).

## Configuration

All contract metadata lives in `src/contracts/`:

- `Provenance.json` – ABI generated by Hardhat.
- `deployment.json` – populated by deployment scripts. Example:

```json
{
	"network": "Sepolia Testnet",
	"chainId": 11155111,
	"contractAddress": "0x...",
	"blockExplorer": "https://sepolia.etherscan.io"
}
```

Optional environment vars (create `frontend/.env` if needed):

```
REACT_APP_SEPOLIA_RPC_URL=https://your-rpc-provider
```

> The frontend never stores private keys. MetaMask handles signing.

## Install & Run

```bash
# 1. Install frontend deps
cd frontend
npm install

# 2. Start the dev server (auto-opens http://localhost:3000)
npm start

# 3. Build production bundle
npm run build
```

If you are testing against a local Hardhat network, keep these in separate terminals from the repo root:

```bash
npm run node             # spawns Hardhat network on 127.0.0.1:8545
npm run deploy:local     # deploys contracts + seeds sample data
```

Once the deploy script completes, reload the React app so it picks up the refreshed `deployment.json`.

## Role-Based Dashboards

After connecting your MetaMask wallet, the UI checks `hasRole` for all AccessControl roles and renders the correct dashboard.

| Role | Capabilities |
| --- | --- |
| Producer | Register new batches (auto-generates batch IDs, accepts IPFS hash). |
| Supplier | View received batches and update status as shipments move. |
| Retailer | Track in-stock items and transfer to consumers when sold. |
| Consumer | View purchased products plus their immutable history. |
| Regulator | Audit products, flag anomalies, and (if also admin) grant/revoke roles. |

Additional workflow helpers:

- **Use Test ID** button in Product Verification quickly loads a known batch hash.
- Status badges use consistent color coding across components (`getStatusColor`).
- Wallet header includes a **Switch Account** button to reopen the MetaMask selector without disconnecting.

## Admin & Regulator Tools

Admins (DEFAULT_ADMIN_ROLE) unlock extra UI:

1. **Role management** – grant/revoke producer/supplier/retailer/consumer/regulator roles on-chain.
2. **Product Explorer** – global list of every registered batch with owner/status history. Selecting a row loads full metadata + timeline.

Regulators without admin privileges still see their owned products via `useAccountProducts` plus the public Product Verification portal.

## Troubleshooting

| Symptom | Likely Cause | Fix |
| --- | --- | --- |
| "Please install MetaMask" toast | Browser has no injected provider | Install MetaMask or use a wallet-enabled browser profile. |
| "Wrong network" banner | Wallet on different chain than `deployment.json` | Click **Switch Network** prompt; UI will call `wallet_switchEthereumChain`. |
| Admin dashboard empty | Wallet lacks DEFAULT_ADMIN_ROLE | Grant the role via deployment script or Hardhat console (`grantRole(DEFAULT_ADMIN_ROLE, address)`). |
| Regulator inventory blank | Deployment lacked any handoffs | Use Producer/Supplier flows (or scripts) to transfer a batch to the regulator. |
| getProductDetails revert | `deployment.json` out of sync | Re-run the deploy script or copy a known-good JSON from `/scripts` output. |

For deeper debugging, open the browser console—components log contract call errors with contextual messages.
